## Context

The vision (Morgan, 2026-09-25): the medium is the only proposer worth
considering besides a human; multi-cursor, multi-shot exploration of
multiverses; the compiler does the codegen, teaches, empowers; "the gradient".
The lens found the tree is a strong compiler with a thin medium on top (about
a tenth of the source serves the proposing surface, zero proposal fixtures),
and the crown — negation, the one property no peer has — leaks in two ways,
one of which needs no negation at all. The seven things I said bothered me
were: I designed where I should have built; the fan/trail mechanism was taken
on faith; the gradient was never measured; `mentl space` was never opened;
the theorem was a plan, not a proof; the e-graph answer was reductive; one
citation came from an abstract. This plan is built from addressing each of
them, read-only, before a line lands. Nothing under the repo was modified;
experiments ran on copies of the tree under the scratchpad.

## What was learned addressing the seven

### 1. The nested-frame fix, built twice on scratch copies (measured)

**Variant A — pass-through** (tee body, both fanout thunks and the lambda
exit finalize their frame row with only the least-solution cut; no
completion prune; a new `inf_exit_nested` op). Boot compiled the patched
wheel (16.4 s, 1.00 GB); the patched wheel compiled itself to a byte-identical
fixpoint (m3 == m4, 13.7 s / 999 MB against the last march's 15.6 s /
1.00 GB); the blob compile's diagnostic set was unchanged (108 = 108). On the
36 banked probes:

| shape | boot | variant A |
|---|---|---|
| `fn run(f) = { let g = () => f(); g() }`, no handler | traps 134 | **refuses at the root, exit 1**; `run`'s row projects `r` |
| `fn run(f) = (() => f())()`, no handler | traps 134 | **refuses, exit 1**; row `r` |
| `fn par(f, g) = (f()) >< (g())` | row `Pure` | row `r + r` |
| `fn run(f) = (f()) ~> h`, `run(() => fop())`, no `F` handler | traps 134 | **still traps 134**; row still `Pure` |
| `fn run(f) with !E + !F = (f()) ~> h` | traps 134 | still 134 |
| every other row | — | identical to boot |

So pass-through fixes the lambda and fanout shapes and not the tee shape.
The tee's drop is one line later: `read_bound_row` (`infer.mn:9138`, one
caller, the tee at `:4350`) chases the finalized body row; a single-edge open
row is followed as an ALIAS to the free cell, and the reader's `_ =>
mk_ef_pure()` catch-all returns `Pure` — the `_ => <fabricated value>`
surrender fallback CLAUDE.md names. (Hypothesis from the read; variant B
tests it.)

**Variant A is refuted by the wheel** (`mentl check src/main.mn` under the
patched compiler): **163 `E_EffectMismatch`** across 18 modules (lists 18,
pipeline 15, lower 13, query 13, json 11, lsp 11, main 10, driver 8, …), e.g.
`spec_pairs_add(pairs, root, t) with Memory + Alloc` — a function with no
lambda, tee or fanout — projecting `Memory + Alloc + GraphRead`, and
`lib/lists.mn`'s most basic functions carrying `GraphRead`, a compiler
effect no library code performs. The mechanism, from the prune's own
comment and the code: a nested frame that no longer prunes keeps SCRATCH
edges (an instantiated callee's unbound row copy, e.g. `iterate`'s inside
`find`'s tee) behind the mask cell `diff_row` mints; the declaration's exit
prune keeps a bound edge whole ("reads fold it") and never recurses, so the
scratch cell is neither dropped nor quantified, and the first caller whose
context binds it writes that caller's effects into the library function's
published row for every later caller. That is the disconnected-vars class
the second-pass deletion named as a hazard, reached from the other side.
**The measurement is the design correction: nested frames must drop
scratch exactly as declarations do; what they must not drop is a cell the
ENCLOSING signature reaches.**

**Variant B — inherited keep-set** (the adversarial pass's C1): each frame
records its parameter cells (`inf_frame_params`); a nested exit prunes with
`signature_free_roots` over the WHOLE frame stack, so the enclosing
declaration's parameter row cells survive and scratch still drops; plus
`read_bound_row`'s catch-all becomes "the edge to that cell"
(`mk_ef_open([], handle)`). **Results (measured):** the boot compiled the
patched wheel (12.2 s, 1.00 GB, zero new blob diagnostics — 108 = 108).
Every prune shape is fixed, and nothing else moved:

| shape | boot | variant B |
|---|---|---|
| `fn run(f) = (f()) ~> h`, `run(() => fop())`, no `F` handler | traps 134 | **refuses at the root, exit 1**; `run : … with !E + r` |
| `fn run(f) with !E + !F = (f()) ~> h`, `main() with !F = run(() => fop())` | accepts, traps 134 | **`E_EffectMismatch` at check** — `F` under `!F` caught |
| the same, no handler in `main` | traps 134 | refuses, exit 1 |
| `fn run(f) = { let g = () => f(); g() }`, no handler | traps 134 | refuses, exit 1; row `r` |
| `fn run(f) = (() => f())()`, no handler | traps 134 | refuses, exit 1; row `r` |
| `fn par(f, g) = (f()) >< (g())` | row `Pure` | row `r + r` |
| the other 30 rows (vacuous class, controls, annotated forms) | — | identical to boot |

The wheel under the patched compiler: **one** `E_EffectMismatch`
(`synth_proposer.mn:927`, `verify_each_enriched`: declared row lacks
`Cast(GNode)`, which a callback inside its nested frame performs — a real
under-declaration the prune had hidden), against 163 under variant A. The
m3 leg refused on that one site (the blob compile treats it as an error),
so the landing carries the one-word row fix and re-measures the fixpoint
after it. The first patch of variant B had a type error (a frame literal
without the new field at two sites, `E_TypeMismatch` ×2, silently
miscompiled into a trap on every program with the class unarmed) — a
measured reminder that `E_TypeMismatch` in the wheel's own source must
refuse the executable.

Two more measured facts: the blob compile's `T_OverDeclared` set is
identical under variant A (so the wheel's *declared-row* narrations did not
move; the mismatches are all inferred rows that GREW); and the wheel's
declared positive rows are wrong wherever a callback's row was dropped —
which makes SYNTAX's own rule (author negations; infer and project the
positive row) a dependency of the crown arc rather than a style note.

### 2. The fan, the trail, and the first divergence (read, with measurements on existing fixtures)

- **Allowed row at a hole is the enclosing function's AUTHORED clause**
  (`cursor.mn:646-655`, `enclosing_fn_scan` at `:678` → `build_declared_row`,
  `effects.mn:190-234`); an undeclared function yields `Pure`
  (`effects.mn:207-210`); a `~> h` installed around the hole is never read.
  Consumed at `synth_proposer.mn:252`. Measured consequence: in
  `fn main() -> Int = (??) ~> h` an effectful candidate is refused by a
  row nobody wrote.
- **Enumeration** (`synth_proposer.mn:129-160`, `:192-220`): vocabulary
  first — only ZERO-argument `FnScheme`s (`:244-273`); then by target head:
  constructors, one lambda skeleton for `TFun`, `0, 1, -1` for `Int`,
  `0.0, 1.0` for `Float`, domain seeds for refinements (`verify.mn:277`
  `ty_domain`), `[]`/`[??]` for lists, a tuple of holes. A pipe-stage hole
  binds to a `TFun`, so `5 |> ??` with `double`/`inc` in scope yields only
  the lambda skeleton — measured on the nearest fixture as "no proposal".
- **Judgment** (`:756-771`, `:885-895`, verified in the source this
  session): `graph_push_checkpoint()` → `world_top()` → `infer_expr(node)`
  under `infer_ctx ~> fresh_for_inference ~> resume_summaries_ctx` →
  `unify(hole_h, h)` → `verify_after_apply && refinement_admits` →
  `graph_rollback(cp)` → `world_restore(w)` → `branch_join` for the proven.
  Sequential `map` (`:742`); zero `><`, `spawn_task` or `Schedule` in the
  proposer. No `heap_mark` in the bracket, although three comments and a
  ledger entry say there is one. The `verify_candidate` op (`mentl.mn:125`)
  has no caller.
- **The trail records handle + prior value per write** (`Mutation =
  MSetNode(h, old) | MSetRow | MSetBoundary | MFreshNode`, `types.mn:971-979`;
  `graph.mn:541-546`). A candidate's segment is readable only between the
  judgment and the rollback; at rollback `trail_len` returns to the
  checkpoint and the next candidate's first append overwrites entry 0 of
  the previous one. No `GraphRead` op exposes the trail. So the
  first-divergence question is computable in principle (the data is there
  for one candidate at a time) and needs one new op: copy `trail[cp ..
  trail_len)` before rollback, filtering path-compression writes
  (`graph.mn:641-644`). RESIDUE already records that on the existing
  fixtures the hole cell is bound to the return cell before proposing, so
  the unify writes nothing and the diff is empty — the fixture must leave
  the cell genuinely free.
- **Acceptance is a text patch**: `apply_suggestion`
  (`cursor_transport.mn:266-285`) → `replace_span` → `fs_write_file` →
  `driver_check` (full re-derivation). `render_candidate_source` renders
  only `name()`, a bare `VarRef` or a literal; lambdas, lists and records
  render as `??`, so accepting them is a no-op. The IDE regex-parses the
  `Propose:` text (`ide/index.html:991-1033`). No `GraphWrite` op is
  performed on accept; the one site holding both handles is
  `cursor_transport.mn:275-276`.
- **Ranking**: `rank_of` (`:386-403`) = `0.5 + scope_distance_decay(hole,
  decl) + Σ decay over refs`; every non-call shape ranks a flat `0.5`; ties
  keep enumeration order.
- **Verdict**: `VNone | VFill | VAsk(divergence)`; `divergence_of`
  (`:1046-1065`): row split first (`DivRow`), then `candidate_denotation`
  by `node_const` (a zero-arg call's body constant), `DivShape` when
  unreadable, `DivName` when all equal, else `DivValue(ty_domain)`. Measured
  renders (existing fixtures): one survivor fills (`Propose: 1 — inferred

  refinement would".
- Stale citations: `src/oracle.mn` does not exist but is cited at

### 5. The theorem: lemma (i) through a mask, done by hand

Done, and moved to its one home: LENS §2.3 carries the hand proof (the bind through a mask splits into a ground check on the folded value and a push `G_v := G_v ∩ (G ∪ mask)`; masks on a path accumulate by union; two paths meet by intersection; no false-mismatch class because a gate refuses only a contradicting write), the twelve shapes searched without a fifth counterexample, and the base calculus verified from the paper bodies (Bauer–Pretnar and Hillerström–Lindley are both monomorphic set-row calculi with handler subtraction; no published proof combines `lacks`-style gates with it, so lemma (i) is new). The three-walks-agree obligation it names was measured the same day by the nested-frame fix's refuted first form (scratch behind a mask cell, neither dropped nor quantified).

### 6. The e-graph: the sharper question, answered

The six rules (`egraph.mn`): add/mul/sub/div identity, mul-absorb, integer
const-fold — arithmetic peepholes on the lowered tree; `saturate_range` is
dead on the fan path. SYNTAX refuses redundant forms at the surface and
`fmt` has a fixpoint, so SPELLING variance never reaches the graph; the only
form variance that exists is SEMANTIC (two bodies, one denotation:
`fold(0, add, xs)` and `sum(xs)`). The proposer already classifies that tie
(`DivName`) and §11.1 already says a same-denotation tie is a meaning tie at
the intent altitude that the medium ASKS about. So the e-graph's role in the
vision is one thing: to DECIDE same-denotation cheaply, by canonical root —
the canon column the medium already has, applied at the proposer (dedupe
survivors by `graph_canon_at` root before classifying) — plus a rule set
that grows with the workload (stage fusion, fold laws) and `~> Cost` off the
default chain. It is not a search structure and not a separate subsystem.
The miscompile (absorb drops a trap) is closed by partiality as a row fact.
"Delete it" loses the same-denotation read; "keep it as an optimizer" keeps
a miscompile and a dead search role.
